# NZ Retail Sales Forecasting

[![Run project](https://github.com/harsha089999/nz-retail-sales-forecasting/actions/workflows/run.yml/badge.svg)](https://github.com/harsha089999/nz-retail-sales-forecasting/actions/workflows/run.yml)

**Quarterly retail sales forecasts by industry, three competing models, error bands, and a Power BI-ready export.**

> **About the data:** everything in this repo is simulated, generated by the code with a fixed random seed so results are reproducible. The numbers describe the simulation, not the real world. Each project says how to swap in a real dataset.

## The business question

How much will New Zealand retail spend be over the next four quarters in each industry, and how confident can we be in that number?

## What this project does

A retailer's planning team needs a forecast they can trust and read in a dashboard, not a notebook. For each of five industries this script backtests three models on the most recent 8 quarters, picks the most accurate one for that industry, refits it on all the history and forecasts 4 quarters ahead with an 80% interval.

## The data

Quarterly sales from 2010Q1 to 2026Q2 for five industries (supermarket and grocery, hardware and garden, fuel, clothing and footwear, food and beverage services). Each series has a linear trend, a Q4 peak, small random noise and a one-quarter shock in 2020Q2 (a COVID-style dip). Values are fictional NZD millions.

## How it works

1. Build a tidy table with one row per industry per quarter (`make_synthetic()`).
2. For each industry, hold out the final 8 quarters as a test set.
3. Fit three models on the rest: **seasonal naive** (repeat last year's pattern), **Holt-Winters** (additive trend and seasonality, statsmodels) and **SARIMA(1,1,1)(0,1,1,4)**.
4. Score each model by MAPE on the 8 test quarters and keep the lowest.
5. Refit the chosen model on the full history and forecast 4 quarters ahead.
6. Build an approximate 80% band as forecast ± 1.28 x the standard deviation of the test errors.
7. Write the actuals and forecasts to one CSV, plus a table of model scores.

## Run it

```bash
git clone https://github.com/harsha089999/nz-retail-sales-forecasting
cd nz-retail-sales-forecasting
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python src/main.py
```

It runs in about 15 seconds or less on a laptop and writes its files to `outputs/`. Python 3.10 or newer is recommended.

## Results from the included run

This is the actual console output when the script is run as shipped:

```text
industry        model  test_mape
     Clothing and footwear       sarima       0.42
Food and beverage services       sarima       1.50
            Fuel retailing       sarima       1.18
       Hardware and garden holt_winters       0.74
   Supermarket and grocery holt_winters       1.29
```

SARIMA won for three industries and Holt-Winters for two, with test MAPE between 0.4% and 1.5%. Those errors are tiny because the simulated series are clean. Real Stats NZ series are noisier, so expect higher errors; the value of the project is the process (compare models fairly, pick per series, show uncertainty), not the numbers.

## Output files

| File | What it contains |
|---|---|
| `outputs/forecast.csv` | Actuals and forecasts stacked: `industry, quarter, type (actual/forecast), sales_nzd_m, lower_80, upper_80, model`. |
| `outputs/model_scores.csv` | Test MAPE for every model and industry, with a `chosen` flag. |

## Limitations and honest caveats

- The interval is approximated from the spread of backtest errors. It is not a model-based prediction interval.
- There is a single train/test split. Rolling-origin cross-validation would give a more reliable accuracy estimate.
- The 8 test quarters contain no shock, so the backtest says nothing about how the models cope with another COVID-style event.
- No outside drivers (CPI, population, interest rates) and the SARIMA orders are fixed rather than searched.

## Using real data

Download the Retail Trade Survey quarterly series by industry from Stats NZ Infoshare (infoshare.stats.govt.nz), reshape it to the columns `industry, quarter, sales_nzd_m`, and replace `make_synthetic()` with a loader. Nothing else needs to change.

## Turning it into a dashboard

Line chart of actual vs forecast with the 80% band shaded, an industry slicer, a KPI card for next quarter's forecast, and a small table of model accuracy so viewers can see why a model was chosen. Load `forecast.csv` straight into Power BI or Tableau.
